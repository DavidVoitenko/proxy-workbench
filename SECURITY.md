# Security Policy / Политика безопасности

## Supported versions / Поддерживаемые версии

| Version | Supported |
| --- | --- |
| 1.3.x | Yes |
| 1.2.x | Security fixes only on request |
| Older versions | No |

Исправления безопасности публикуются для актуальной ветки `main`. Обновляйте локальную копию и зависимости после выхода новой версии.

## Reporting a vulnerability / Как сообщить об уязвимости

Не публикуйте рабочий exploit или технические детали уязвимости в открытом issue, pull request или discussion.

1. Используйте приватный интерфейс **Security → Advisories → Report a vulnerability** в репозитории.
2. Если приватная отправка недоступна, создайте минимальный issue **без** деталей эксплуатации и попросите открыть приватный канал для продолжения.
3. Дайте maintainers достаточно времени на подготовку исправления до публичного раскрытия.

Полезная информация для report:

- affected version или commit;
- описание воздействия и вероятный сценарий;
- минимальный reproduction на локальных mock-сервисах или synthetic fixtures;
- ожидаемое и фактическое поведение;
- возможное mitigation, если оно очевидно.

Не отправляйте credentials, tokens, cookies, private proxy endpoints, реальные персональные данные, содержимое `data/`, machine-specific paths или hostname. Перед отправкой замените эти значения нейтральными fixtures.

## Response process / Обработка

Maintainers подтверждают получение report в разумный срок и согласуют разумный срок исправления. Конкретный SLA не гарантируется, но безопасность пользователей и защита reporter имеют приоритет.

После исправления maintainers могут:

- подготовить patch и regression test на локальных mocks;
- объединить исправление в `main` и обновить changelog;
- раскрыть детали после появления исправления;
- запросить дополнительные сведения через приватный канал.

## Security boundaries / Границы ответственности

Proxy Workbench — локальный инструмент для сбора и проверки публичных прокси. Он не гарантирует анонимность, безопасность или стабильность стороннего прокси и не должен использоваться для обхода законов, политик безопасности или условий сервисов.

Источники по умолчанию ограничены публичными адресами, redirects проверяются, а выбранный DNS address закрепляется на transport. Локальный `--allow-private-sources` предназначен только для доверенных mock-сервисов и не должен использоваться с недоверенными URL.

Проверка через внешний прокси невольно раскрывает этому прокси IP-адрес, назначение и время сетевого запроса. Проверяемый сервис видит IP-адрес прокси. Пользователь обязан самостоятельно оценить legal, ethical и privacy consequences.

Проект не проводит внешний security scan. CI использует только локальные mock-сервисы и unit tests; dependency installation в CI является инфраструктурной загрузкой pinned packages, а не сетевой проверкой приложения.
