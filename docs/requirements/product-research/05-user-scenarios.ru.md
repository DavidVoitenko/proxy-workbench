# Сквозные сценарии Proxy Workbench

Дата: 25 сентября 2026. **35 сценариев: 13 обязательных и 22 дополнительных.** Это целевое поведение продукта; нынешние возможности и обходные пути отмечены отдельно. Сценарии не означают, что все функции уже существуют или входят в ближайший релиз. Код и сеть не запускались; основа — статическое чтение проекта. Частота и спрос — гипотезы для дальнейшей проверки, без вымышленных интервью и метрик.

Термины согласованы с [моделью продукта](01-product-model.ru.md): endpoint — протокол + host + port; доступ — endpoint + credential reference и параметры поставщика; коллекция — именованное членство доступов; профиль — версионированные проверки и правило принятия; задание — выполнение над заданным scope; наблюдение — измеренная проба; пул — желаемое состояние пригодных членов, поддерживаемое контроллером. Неизвестное, провал и пропущенное измерение различаются. Старый успех не заменяет свежий отказ. После смены сети нужна перепроверка до обещания текущей пригодности.

Ниже «минимум» означает наименьшее законченное улучшение относительно существующего кода, а не обязательство реализовать всё сразу. Общая приёмка сценариев должна проверяться локальными mocks и изолированными данными; реальную географию и доступность внешних сервисов нельзя обещать по одному локальному тесту.

## Обязательные сценарии

### S01. Быстро получить несколько просто работающих прокси

**Кто и когда:** обычный пользователь Windows/macOS; предположительно эпизодически, при появлении задачи.

- **Вход:** «Найти 5 рабочих», публичные источники, без ручного URL.
- **Действия:** выбрать встроенный базовый профиль; показать контрольные обращения и бюджет; приоритизировать свежих известных кандидатов; собрать, дешёво отсеять и проверить передачу; публиковать пригодные результаты до конца полного обхода.
- **Результат:** до 5 адресов, доказанная capability, возраст проверки, «Скопировать» и «Подключить». Если найдено 3, это честный частичный итог.
- **Ошибки:** источники пусты, контрольный target недоступен, бюджет исчерпан, адреса не проходят передачу.
- **Восстановление:** объяснить этап воронки; повторить ограниченную пробу, сменить разрешённые источники или увеличить бюджет по выбору пользователя; N не гарантировать.
- **Сейчас / обход:** default example.com уже позволяет HTTP-проверку без ввода URL; `--want` и приоритет известных адресов есть. Но сбор предшествует scan, а UI начинает с сервисных настроек.
- **Минимум:** самостоятельный basic-режим с версией, точным смыслом успеха, поддерживаемой политикой endpoints и кнопкой «найти несколько». Потоковый сбор — отдельное последующее ускорение.

### S02. Получить прокси конкретной страны

**Кто и когда:** обычный и продвинутый пользователь; предположительно на старте каждой географической задачи.

- **Вход:** «Германия или Нидерланды», указать, нужна страна endpoint или наблюдаемого выхода; исключения и unknown — явно.
- **Действия:** разрешить поиск по названиям; проверить наличие/возраст GeoDB; применить подходящий предфильтр; если нужен выход — измерить его judge-пробой. Endpoint DE нельзя отсечь только потому, что желаемый выход NL.
- **Результат:** список с отдельными endpoint country, exit country, источником и датой знания.
- **Ошибки:** GeoDB отсутствует/устарела; выход неизвестен; поставщик заявил одну страну, наблюдается другая; квота невыполнима.
- **Восстановление:** обновить базу, перепроверить выход, показать unknown отдельно, предложить изменить конкретное правило; не заменять его автоматически.
- **Сейчас / обход:** страны по ISO-кодам, несколько стран, GeoIP/ASN и отображение endpoint→exit уже существуют. Пользователь вручную понимает, что именно фильтруется.
- **Минимум:** страны по названиям и явный выбор семантики country-фильтра, unknown и freshness; квоты — после основы пулов.

### S03. Найти прокси для одного или нескольких сервисов

**Кто и когда:** все три группы; по настройке задачи и при повторной проверке.

- **Вход:** выбрать один сервис или, например, сайт GitHub и публичный endpoint своего API; обязательные проверки в профиле.
- **Действия:** загрузить версии presets; показать конкретные probes и условия; выполнить их, сохранив раздельные наблюдения.
- **Результат:** матрица «какая capability прошла» и итог профиля. HTTP-проверка страницы Telegram не называется проверкой звонков.
- **Ошибки:** preset устарел, HTTP 200 содержит заглушку, API вернул ожидаемый отказ авторизации, один target недоступен.
- **Восстановление:** показать assertion/stage; обновить или скопировать preset, повторить изменённые probes. Ожидаемый 401 может доказывать сетевой доступ к endpoint, но не возможность работы с аккаунтом.
- **Сейчас / обход:** девять presets, произвольные targets, GET/HEAD, statuses, contains/hash и логика «все» уже есть. Разные задачи решаются отдельными запусками.
- **Минимум:** каталог с поиском, названиями capabilities, версией и наборами; сохранённый профиль использует зафиксированную ревизию.

### S04. Проверить собственный файл

**Кто и когда:** обычный пользователь, разработчик; после каждой новой поставки адресов.

- **Вход:** TXT/clipboard, позднее CSV/JSON; выбор новой или существующей коллекции.
- **Действия:** preview до записи: распознано, duplicate, invalid с номерами строк; выбрать merge/replace; транзакционно импортировать membership и provenance; проверить только выбранную коллекцию.
- **Результат:** пригодность собственных записей, отчёт импорта и история конкретной поставки.
- **Ошибки:** разделитель/кодировка/формат неизвестен, IPv6 записан неверно, часть строк ошибочна, файл усечён.
- **Восстановление:** исправить строки или импортировать явно выбранные валидные; replace показывает diff; ошибка не стирает старый состав.
- **Сейчас / обход:** файл/вставка/дедупликация существуют; база накопительная. Для файла нужен отдельный `--data`; одноразовый `test` принимает перечисленные аргументами адреса, не файл/`--input`. `--no-sources` не изолирует старую базу.
- **Минимум:** collection scope и preview TXT/clipboard. Остальные форматы не должны задержать безопасную изоляцию своего списка.

### S05. Использовать собственные прокси с авторизацией

**Кто и когда:** разработчик и power user; регулярно при работе с поставщиком.

- **Вход:** hostname/IP, protocol, port, username/password либо поддерживаемая provider-строка.
- **Действия:** preview с маской; отделить endpoint от доступа; сохранить secret reference в подходящем хранилище; выполнить negotiation/auth и затем probes.
- **Результат:** авторизованный доступ участвует в коллекциях/пулах; GUI и обычные exports не раскрывают пароль.
- **Ошибки:** неверные credentials, 407, недоступно OS secret store, hostname меняет адрес, один host:port обслуживает два аккаунта.
- **Восстановление:** исправить/разблокировать секрет, перепроверить только затронутый доступ; auth error не считать общей смертью endpoint.
- **Сейчас / обход:** `normalize` отклоняет hostname и userinfo; авторизация клиента gateway — другой механизм. Пользователь проверяет поставщика другим клиентом или использует поддерживаемый поставщиком доступ без пароля вне Workbench.
- **Минимум:** hostname + HTTP CONNECT/SOCKS5 username/password через access identity/secret reference, redaction во всех выводах; headless/portable без молчаливого plaintext fallback.

### S06. Организовать списки для разных проектов

**Кто и когда:** разработчик и power user; предположительно ежедневно.

- **Вход:** «Каталог товаров» и «Тестирование API», по коллекции и профилю; один доступ может входить в оба списка.
- **Действия:** запуск фиксирует scope; результаты/экспорт/подключение показывают коллекцию и профиль; views не меняют другой проект.
- **Результат:** две независимые рабочие задачи без дублирования идентичности адресов и без взаимного загрязнения.
- **Ошибки:** пользователь выбрал не тот scope, replace затрагивает общий endpoint, профиль изменён во время job.
- **Восстановление:** явный summary перед запуском/replace; undo членства; job продолжает immutable revision; переключение профиля не выдаёт старые результаты за новые.
- **Сейчас / обход:** hash profiles существуют, GUI ориентирован на last-profile. Отдельные data directories/settings files дают грубое разделение.
- **Минимум:** именованные коллекции и профили, scope в каждом job/export/result. Отдельный workspace/team/project hierarchy не нужен.

### S07. Постоянно поддерживать нужный рабочий пул

**Кто и когда:** разработчик и power user; постоянно для потребляющего приложения.

- **Вход:** «20 свежих, резерв 10, возраст не более 15 минут, только эти коллекции/источники», budgets и политика уведомлений.
- **Действия:** проверить резерв, ранее известные разрешённые записи, затем обновить разрешённые источники; выполнять recheck, cooldown, probation и повторный допуск; не менять eligibility правила.
- **Результат:** pool healthy/degraded/depleted с фактическим числом пригодных и причиной дефицита, стабильный local gateway route.
- **Ошибки:** все участники не прошли, источник недоступен, бюджет/квоты исчерпаны, target outage.
- **Восстановление:** bounded backoff, уведомление на переход/восстановление; действия по конкретной причине. При нуле клиент получает `pool_empty`, без DIRECT и без подмешивания чужих списков.
- **Сейчас / обход:** `watch` периодически перепроверяет только прошедших; новый сбор/пополнение пользователь запускает вручную.
- **Минимум:** один named pool с N, резервом, freshness, бюджетом и пополнением; сложный cron и множество конкурентных пулов отложить.

### S08. Подключить браузер, приложение или скрипт

**Кто и когда:** обычный пользователь при первом подключении, разработчик при интеграции.

- **Вход:** выбрать рабочий список/пул и потребителя: браузер, приложение с proxy settings, curl/Python.
- **Действия:** показать точный HTTP/SOCKS/PAC адрес, copy example, выполнить ограниченную пробу Workbench→gateway→upstream→target; отдельно получить контрольный запрос именно выбранного клиента; рассказать, как отключить.
- **Результат:** применённое пользователем подключение; control route и реальное client connection имеют отдельные статусы. Проба Workbench сама по себе не доказывает настройки браузера/приложения.
- **Ошибки:** порт занят, приложение не поддерживает proxy/auth, PAC применён к другой сети, пустой пул, выбран неподдерживаемый upstream protocol.
- **Восстановление:** показать неисправный этап, предложить подходящий способ/порт; повторить probe; вернуть прежние настройки, если приложение их меняло.
- **Сейчас / обход:** gateway/PAC/Clash/sing-box exports, Telegram link, API и примеры уже существуют; пользователь соединяет их по README.
- **Минимум:** мастер подключения поверх существующих функций, явный scope и диагностика; системные proxy settings не менять скрытно.

### S09. Управлять через GUI, CLI и API

**Кто и когда:** разработчик и power user; в повседневных скриптах и CI.

- **Вход:** один profile revision и collection ID, команда/запрос запуска.
- **Действия:** общий слой валидации/операций создаёт job ID; GUI/CLI/API читают одни статусы и наблюдения; изменение request получает idempotency key.
- **Результат:** одинаковые правила и состав пригодных; CLI JSON/NDJSON с schema version и exit codes; API pagination привязана к snapshot.
- **Ошибки:** повтор запроса после обрыва, несовместимая schema version, read token пытается изменять, writer занят.
- **Восстановление:** вернуть прежний job для повторного key, ясный validation/auth/conflict response; очередь с одним writer; повторить чтение с cursor.
- **Сейчас / обход:** есть CLI, read API и GUI API команд; пользователь склеивает lifecycle shell-скриптами.
- **Минимум:** documented jobs create/status/cancel/resume и общий service layer; API не требует новой очереди сообщений/облака.

### S10. Оставить программу работать в фоне

**Кто и когда:** обычный пользователь и power user; часами или постоянно.

- **Вход:** «Закрывать окно, сохраняя фон»; опциональный автозапуск.
- **Действия:** tray/menu bar показывает активное задание/пул, следующий запуск, открыть/пауза/выход; UI и worker имеют ясный lifecycle.
- **Результат:** закрытие окна сохраняет разрешённые фоновые задачи и gateway; «Выйти» завершает их предсказуемо.
- **Ошибки:** OS logout, ручное завершение, повторный запуск, попытка обновления при active job.
- **Восстановление:** восстановить persisted состояние, показать interrupted/paused, открыть существующий instance; restart/autostart следуют выбранной политике.
- **Сейчас / обход:** браузерную вкладку можно закрыть, терминал должен оставаться; повторный запуск открывает существующий GUI. Есть Docker/CLI для фона.
- **Минимум:** tray/menu bar и ясные lifecycle-команды с opt-in autostart, без переписывания web UI; отдельное окно вторично.

### S11. Понять причину отсутствия результатов

**Кто и когда:** все группы; каждый раз, когда вывод пуст.

- **Вход:** job завершился с нулём пригодных либо прогресс давно не даёт результата.
- **Действия:** воронка input→valid→scope/geo→protocol→probes→fresh/eligible; группировать причины по target/stage, показывать sample counts и health evidence.
- **Результат:** различены «не загрузили», «всё исключено», «нет данных о стране», «не прошли», «устарели», «нет сети», «бюджет кончился».
- **Ошибки:** baseline сам упал; direct target доступен, а proxy path нет; слишком мало наблюдений для общего вывода.
- **Восстановление:** показывать подозрение и границы доказательства; выполнить малую контрольную проверку по разрешённой политике, исправить конкретное правило/источник и повторить затронутую часть.
- **Сейчас / обход:** source report и per-attempt errors есть, пользователь вручную сопоставляет их с настройками.
- **Минимум:** partition counters, reason codes и следующее действие; контроль сети/target не превращается в автоматическое занижение рейтинга всех поставщиков.

### S12. Восстановиться после остановки, сна, смены сети или сбоя

**Кто и когда:** все; непредсказуемо, особенно на ноутбуке.

- **Вход:** stop, sleep/wake, Wi-Fi сменился, процесс аварийно завершён.
- **Действия:** сохранять checkpoints и completed observations, interruption reason; новый network epoch при смене сети; при старте восстановить job и предыдущий целостный export generation.
- **Результат:** resume незавершённого с понятной свежестью; старое наблюдение доступно как история, а не доказательство работы в новой сети.
- **Ошибки:** write прерван, running state завис после crash, второй процесс пытается писать, версия профиля уже другая.
- **Восстановление:** один writer/lease, повтор in-flight элемента, immutable revision; выбор resume/cancel; перед допуском в current pool — контроль новой сети и перепроверка.
- **Сейчас / обход:** SQLite resume обычного первоначального scan, stop и export generations существуют; recheck предварительно удаляет старые rows и требует отдельного исправления сохранности. Пользователь перезапускает `scan`/GUI и вручную разбирается с контекстом.
- **Минимум:** durable job identity и причины состояния поверх существующего resume; сон/сбой устройства не записывать как измеренный proxy fail.

### S13. Сравнить качество источников или собственных поставщиков

**Кто и когда:** power user и разработчик; при выборе источников и периодическом обслуживании.

- **Вход:** два source/provider connections, один профиль, comparable окно, сеть и бюджет.
- **Действия:** показать checked denominator, unique fresh passes, overlap/source families, marginal contribution, age и непроверенную часть; при нужде сформировать сбалансированную выборку.
- **Результат:** прозрачное обоснование, что источник добавляет и при каких условиях; не «поставщик надёжен 99% времени» по трём пробам.
- **Ошибки:** разные объёмы, early-stop bias, mirrors, общий target outage, одна страна преобладает.
- **Восстановление:** пометка несопоставимости, повтор с одинаковым budget/sampling, reversible disable; отличать first-seen attribution от полезного вклада.
- **Сейчас / обход:** source quality и candidate_seen есть; пользователь сравнивает exports и source report вручную.
- **Минимум:** корректные знаменатели, overlap/family и marginal count; ручные cost-поля позже, без marketplace.

## Дополнительные сценарии

### S14. Проверить обязательный сервис и «любой / все / не менее K» дополнительных

**Кто и когда:** разработчик/power user; при создании многосервисной задачи.

- **Вход:** обязательное API и минимум 2 из 3 вспомогательных probes.
- **Действия:** валидация mandatory/optional policy; выполнить и агрегировать отдельно; при fail-fast записать skipped.
- **Результат:** all mandatory AND выбранное правило optional; показываются недостающие возможности.
- **Ошибки:** K больше числа probes, `any` при пустом optional, unknown по обязательному probe, старый partial результат недостаточен.
- **Восстановление:** исправить правило до старта или допроверить missing probes; пустой optional разрешён только с явным `none`.
- **Сейчас / обход:** все targets обязательны; нужны отдельные запуски и ручное объединение результатов.
- **Минимум:** общий evaluator all/any/K с truth-table tests и visible policy; mandatory невозможно нечаянно сделать optional.

### S15. Проверить содержимое собственного API

**Кто и когда:** разработчик; регулярно при проверке API-интеграции.

- **Вход:** HTTP API URL, ожидаемый status, JSON path/value/type; ограничение размера/времени.
- **Действия:** HTTP transport→bounded body→JSON parse→assertions; сохранять только безопасные summary/reason codes.
- **Результат:** «поле status равно ok» отдельно от простого HTTP 200.
- **Ошибки:** HTML CAPTCHA вместо JSON, key отсутствует, неверный тип, слишком большой/deep JSON.
- **Восстановление:** увидеть конкретный matcher, исправить профиль либо endpoint и повторить; не включать произвольный код в assertions.
- **Сейчас / обход:** statuses/contains/SHA-256 существуют; сложную проверку разработчик делает собственным скриптом.
- **Минимум:** ограниченный declarative JSON matcher без interpreter. Секрет target API — отдельная будущая policy, не proxy password и не снятие запрета на credential headers.

### S16. Проверить WebSocket или длительное соединение

**Кто и когда:** разработчик/power user; при интеграции realtime-приложения.

- **Вход:** разрешённый WebSocket endpoint, bounded duration, handshake/ping/pong policy.
- **Действия:** отдельный probe фиксирует upgrade, удержание, latency/причину закрытия; соблюдает connection/time budget.
- **Результат:** конкретная WebSocket capability за измеренное окно, отдельно от сайта/API.
- **Ошибки:** HTTP 200 вместо 101, handshake прошёл, pong отсутствует, upstream закрыл канал до срока.
- **Восстановление:** отметить стадию, проверить свой endpoint, повторить ограниченное измерение; существующий HTTP pass не менять ретроспективно.
- **Сейчас / обход:** preset Discord проверяет HTTP endpoint; полноценный WS-проход нужен внешним скриптом/клиентом.
- **Минимум:** один typed WebSocket runner на собственном/разрешённом endpoint; широкие публичные presets после поддержки и budget policy.

### S17. Проверить передачу медиа и скорость под ограниченным бюджетом

**Кто и когда:** обычный/power user; изредка для загрузки или медиа.

- **Вход:** bounded media/range probe, лимит байтов, нужный throughput; опционально один согласованный тестовый файл.
- **Действия:** после дешёвой пригодности измерить небольшой сегмент/загрузку; показать bytes, duration, способ измерения и количество проб.
- **Результат:** скорость конкретной загрузки/передачи; без обещания DRM, подписки, воспроизведения всего видео или звонков.
- **Ошибки:** Range не поддержан, body слишком велик, target ограничил скорость, cache и короткий замер искажают результат.
- **Восстановление:** ограниченная повторная проба/другой поддерживаемый endpoint; сохранять measured limits, не усреднять несопоставимые измерения молча.
- **Сейчас / обход:** speedtest URL, Мбит/с и сортировка уже есть; пользователь вручную проверяет конечное приложение.
- **Минимум:** объяснение существующего замера и budgets; media capability — только при отдельном воспроизводимом probe.

### S18. Регулярно обновлять подписку своего поставщика

**Кто и когда:** разработчик/power user; после изменения выдачи поставщика, часто ежедневно.

- **Вход:** named subscription URL/adapter, credential reference при необходимости, целевая коллекция и merge/authoritative-replace policy.
- **Действия:** preview первого ответа; следующие refresh фиксируют completeness и атомарный membership diff данного connection.
- **Результат:** актуальный собственный список с provenance; ручные записи и другой connection не удаляются.
- **Ошибки:** 401, timeout, malformed/усечённый ответ, пустой успешный snapshot.
- **Восстановление:** last-good membership и stale label при ошибке; retry/backoff; пустая замена подчинена отдельной явной policy, не автоматическому «всё удалить».
- **Сейчас / обход:** URL источника можно добавить, но user lifecycle и scope ограничены; пользователь повторно импортирует файл.
- **Минимум:** collection-bound connection, manual refresh + preview/diff; расписание после durable jobs.

### S19. Избранное, заметки и массовое временное исключение

**Кто и когда:** обычный/power user; несколько действий за рабочую сессию.

- **Вход:** выделить строки, отметить favourite, добавить note/tag, исключить на час с причиной.
- **Действия:** сохранить metadata с понятным scope; временное исключение влияет на admission, но не удаляет измерения; selection на пагинации явно обозначена.
- **Результат:** управляемый рабочий список и понятные пользовательские решения.
- **Ошибки:** избранный устарел/denylisted, фильтр изменился после выделения, массовое действие затрагивает больше строк, чем ожидалось.
- **Восстановление:** preview count/scope и undo; снять исключение/перепроверить; favourite никогда не обходит требования пригодности.
- **Сейчас / обход:** поиск/фильтры/copy page/denylist есть; отметки ведутся во внешнем файле.
- **Минимум:** row selection/copy selected/add membership/temporary exclusion; tags/columns/saved views после стабилизации коллекций.

### S20. Сохранить одну сессию и знать о смене upstream

**Кто и когда:** разработчик/power user; при серии запросов в течение минут/часов.

- **Вход:** session ID, TTL, policy `strict` или `failover`.
- **Действия:** закрепить доступ к upstream; повторные соединения следуют affinity; уже открытый TCP остаётся на своём маршруте.
- **Результат:** контролируемая сессия, событие о потере/смене; стабильный local gateway не выдается за постоянный exit.
- **Ошибки:** upstream умер/исчез из допуска, provider меняет exit у того же hostname, TTL истёк.
- **Восстановление:** strict возвращает session lost; failover разрешает новый upstream и сообщает событие. Активный поток не мигрируется.
- **Сейчас / обход:** session options, TTL и cooldown уже есть; клиент сам отслеживает фактический exit/сброс сессии.
- **Минимум:** explicit policies и событийная диагностика поверх existing sessions, не новая ротация с нуля.

### S21. Ограничить расход сети и ресурсов ноутбука

**Кто и когда:** обычный/power user; в поездке, на батарее или ограниченном интернете.

- **Вход:** «экономно», максимум bytes/requests/time, без download-speed test; предельная concurrency.
- **Действия:** считать все stages/attempts/judge/speed, соблюдать per-target/source caps; дорогие проверки выполнять после дешёвых; backoff на throttling.
- **Результат:** полезный частичный список и фактический расход, завершение `budget_limited`.
- **Ошибки:** target 429/503, metered network неизвестна, частичный body потребил budget, одновременно активны jobs.
- **Восстановление:** pause/finish с reason и сохранённым результатом; продолжить с новым budget; адаптация не превышает установленный потолок.
- **Сейчас / обход:** global rate, workers fitting, prefilter и max bytes есть; пользователь вручную снижает параметры.
- **Минимум:** общий budget и per-target backoff; native battery detection можно отложить.

### S22. Перенести настройки, списки и историю на другой компьютер

**Кто и когда:** обычный/power user; редко, но с высокой ценой ошибки.

- **Вход:** «Создать резервную копию», выбрать scope; затем файл backup на другом устройстве.
- **Действия:** consistent snapshot с manifest/version/checksum; preview restore в отдельную data directory; показать необходимость повторного ввода OS-bound secrets.
- **Результат:** восстановленные collections/profiles/history, проверенная совместимость, текущие данные не повреждены.
- **Ошибки:** архив повреждён, schema новее приложения, секреты не переносимы, disk full.
- **Восстановление:** reject до изменения активных данных, migration-copy/rollback, secret re-entry; восстановленные observations остаются историей до перепроверки в новой сети.
- **Сейчас / обход:** settings export/import есть; полный перенос выполняется вручную остановкой и копированием data.
- **Минимум:** пользовательский backup/restore-copy без plaintext credentials. До миграции R1 обязательны технический согласованный backup и rollback; полноценный backup UI/merge-restore можно делать позже.

### S23. Повторяемая локальная проверка при разработке

**Кто и когда:** разработчик; в CI и при регрессии транспорта.

- **Вход:** собственный mock proxy/health target, временный scope и versioned profile.
- **Действия:** явно разрешённый локальный режим использует изолированные data/ports; выдаёт deterministic schema/reason codes и cleanup временного job.
- **Результат:** воспроизводимая проверка своего кода без рабочих списков, аккаунтов и внешних scan.
- **Ошибки:** private-address policy не соответствует сценарию, порт занят, mock не запущен, timeout слишком короток.
- **Восстановление:** точное сообщение scope/policy/port; скорректировать локальный fixture, не отключать глобальные проверки загрузчика источников.
- **Сейчас / обход:** repository tests используют mocks; CLI `test` проверяет без хранения, но нормализация proxy ограничена публичными IP. Свои локальные стенды запускаются отдельным кодом.
- **Минимум:** документированный developer fixture path и явный локальный policy scope, если сценарий подтверждён; не автоматически расширять обычный импорт private destinations.

### S24. Собрать пул с разнообразием ASN, сетей и выходных IP

**Кто и когда:** power user/разработчик; для устойчивости к общей точке отказа.

- **Вход:** «10 доступов, минимум 3 ASN, не более 2 с одним измеренным exit IP», допустимые страны/families.
- **Действия:** отделить endpoint diversity от наблюдаемого exit; применять квоты после проверки данных; показать unknown bucket.
- **Результат:** пул с явным выполнением/дефицитом по каждой квоте.
- **Ошибки:** разные endpoints имеют общий выход, ASN неизвестен, quotas конфликтуют, exit изменился после admission.
- **Восстановление:** повторить нужные observations, сообщить дефицит, предложить изменение конкретной квоты; неизвестное не считать уникальным выходом.
- **Сейчас / обход:** ASN/exit data есть; пользователь группирует JSON/CSV внешним скриптом.
- **Минимум:** diversity summary и predicates; active quota controller после обычного N-pool.

### S25. Понять регрессию после изменения профиля или поставки

**Кто и когда:** разработчик/power user; после обновлений и ухудшения результата.

- **Вход:** две profile revisions/job snapshots или import batches.
- **Действия:** сравнить input scope, targets/assertions, версии preset, network epoch, samples и freshness; показать gained/lost/unknown и различия причин.
- **Результат:** проверяемое объяснение, что изменилось; наблюдаемая корреляция не называется доказанной причиной.
- **Ошибки:** разные сети/объёмы, fail-fast дал partial data, targets стали другими, малая выборка.
- **Восстановление:** отметить несопоставимость и предложить малую контролируемую перепроверку под обеими версиями.
- **Сейчас / обход:** hash profiles существуют, GUI не предоставляет полноценных именованных compare flows; пользователь сохраняет экспорты.
- **Минимум:** profile diff и context в snapshots; статистическая лаборатория не нужна.

### S26. Только собрать адреса, не проверяя трафик

**Кто и когда:** power user/разработчик; при подготовке источников или offline обработке.

- **Вход:** разрешённые источники/файл, collection scope, режим «Только собрать».
- **Действия:** parser, validation и dedup сохраняют membership/provenance; не запускаются TCP/service/judge/speed probes.
- **Результат:** распознанные непроверенные кандидаты и source/import report, явно без обещания работоспособности.
- **Ошибки:** adapter ошибочен, source частичен, все строки invalid, источник превысил лимиты.
- **Восстановление:** preview parser/error/limits; повторить источник; не обнулить прежние membership после неполной выдачи.
- **Сейчас / обход:** `collect` и GUI «Собрать адреса» уже есть.
- **Минимум:** самостоятельный режим со своей validation и scope; collected status не выглядит как service pass. Не повторно реализовывать collector.

### S27. Отличить открытый порт от исправного proxy-протокола

**Кто и когда:** разработчик/power user; при диагностике списка с неизвестной схемой.

- **Вход:** host:port, известный protocol либо explicit detection policy.
- **Действия:** отдельные TCP connect и protocol negotiation; сохранять auth requirements/capability; затем по выбору basic transfer.
- **Результат:** «порт доступен», «SOCKS handshake прошёл», «CONNECT отказан» различаются.
- **Ошибки:** порт обслуживает другой daemon, malformed SOCKS reply, proxy требует auth, HTTP доступен, CONNECT нет.
- **Восстановление:** выбрать верный protocol, добавить credentials, перейти к базовому transfer test; unknown не считать pass.
- **Сейчас / обход:** TCP prefilter и auto HTTP/SOCKS4/SOCKS5 detection уже есть; отдельную интерпретацию пользователь выводит из деталей.
- **Минимум:** capability/status model и видимый диагностический режим, без превращения порт-чека в рекомендацию для браузера.

### S28. Экспортировать именно нужную выборку без потери важных свойств

**Кто и когда:** все; при передаче результата потребляющему инструменту.

- **Вход:** selected rows/сохранённый фильтр, формат и назначение экспорта.
- **Действия:** показать count, collection/profile/time и свойства, которые формат поддерживает; опубликовать immutable snapshot; secrets — только по отдельному явно выбранному workflow.
- **Результат:** воспроизводимый файл с понятной областью и предупреждением о несовместимых строках/полях.
- **Ошибки:** hostport теряет protocol/auth/DNS semantics, target format не поддерживает IPv6/тип доступа, пользователь путает table filter с export filter.
- **Восстановление:** другой формат или gateway route; preview exclusions, не тихо отбрасывать auth/TLS настройки; прошлое целостное поколение остаётся при сбое.
- **Сейчас / обход:** множество exports и crash-safe generations уже есть; UI отдельно сообщает, что table filters сами не меняют файлы.
- **Минимум:** единый явный export scope и compatibility report; не новый набор одинаковых форматов.

### S29. Отключить бесполезные зеркала и вернуть источник после ошибки

**Кто и когда:** power user; периодическое обслуживание каталога.

- **Вход:** source report с большим overlap или нулевым результатом.
- **Действия:** показать source family/mirrors, unique contribution, checked denominator, age и ошибки target/network; предложить reversible disable/cooldown.
- **Результат:** экономия сборов без необоснованного удаления источника навсегда.
- **Ошибки:** один плохой run, partial fetch, неслучайная выборка при want N, shared outage.
- **Восстановление:** восстановить disabled, повторить ограниченную сопоставимую выборку; источник остаётся в истории и не возвращается молча при pack update.
- **Сейчас / обход:** prune sources и update sources есть; пользователь редактирует textarea/сохраняет копию списка.
- **Минимум:** disabled state/reason/undo и контекст статистики; глобальный поиск новых источников не дублировать.

### S30. Подготовить диагностический отчёт для issue

**Кто и когда:** все и maintainers; при ошибке, которую не удалось объяснить.

- **Вход:** «Подготовить отчёт» из failed job.
- **Действия:** собрать локальный bounded bundle: версии, schema, masked settings, scope counts, stage/reason codes; показать preview и включённые разделы.
- **Результат:** файл/копируемый текст, который пользователь сам может приложить; ничего не отправляется автоматически.
- **Ошибки:** токены в URL/query/headers, персональные пути, provider credentials, слишком большой log.
- **Восстановление:** redaction до preview/export, исключение адресов/логов, minimal bundle; приватные данные не нужны для воспроизведения многих ошибок на mocks.
- **Сейчас / обход:** README/help/issue templates/logs есть; пользователь вручную копирует и редактирует.
- **Минимум:** безопасный диагностический export и помощь по reason codes, без обязательного аккаунта и скрытой телеметрии.

### S31. Сменить пароль поставщика или разблокировать хранилище

**Кто и когда:** разработчик/power user; при ротации credentials и смене устройства.

- **Вход:** новый credential для выбранного access binding, либо OS vault locked.
- **Действия:** не раскрывая старый секрет, сохранить новую version/ref; пометить затронутые observations требующими auth recheck; сохранить коллекции/происхождение.
- **Результат:** восстановленный доступ без повторного импорта списка; другие аккаунты того же endpoint не меняются.
- **Ошибки:** новый пароль неверен, username меняет provider session/геопараметры, secret store недоступен.
- **Восстановление:** отдельные `auth_failed`/`secret_unavailable`; повторная настройка/разблокировка; новый username с иной семантикой создаёт новый access context.
- **Сейчас / обход:** upstream credentials ещё не поддерживаются; пользователь выполняет ротацию в отдельном клиенте.
- **Минимум:** lifecycle secret refs в той же реализации auth import, а не второй парольный менеджер.

### S32. Поделиться профилем и обновить набор сервисов

**Кто и когда:** разработчик/power user/maintainer; при совместном использовании задачи и обновлении targets.

- **Вход:** declarative profile/pack из файла, проверенная версия, опциональное обновление существующего каталога.
- **Действия:** validate compatibility, preview diff и сетевые обращения; убрать secrets; создать локальную копию/revision; существующие jobs остаются pinned.
- **Результат:** воспроизводимый template для коллег без обязательного аккаунта, сохранённые local overrides.
- **Ошибки:** несовместимый matcher/adapter, скрытый URL/token, новая версия изменила критерий успеха.
- **Восстановление:** reject invalid до записи, сохранить старую ревизию, миграция через явный diff, локальный fork профиля.
- **Сейчас / обход:** config JSON и settings import/export есть; presets встроены в JS.
- **Минимум:** документированная declarative schema, version/pinning и fixtures; исполняемые плагины/marketplace отложить.

### S33. Управлять домашним сервером с ноутбука или телефона

**Кто и когда:** power user; эпизодический контроль headless-инстанса.

- **Вход:** сознательно настроенный защищённый канал к серверу, read/control token; мобильный браузер для статуса.
- **Действия:** responsive status/job/pool UI использует тот же public contract; показывает server identity/context; control-команды идемпотентны.
- **Результат:** удалённое управление заданием; это не проксирование трафика телефона и не доступ к `127.0.0.1` компьютера через телефонный loopback.
- **Ошибки:** канал оборван, token истёк/не имеет scope, два клиента меняют настройки.
- **Восстановление:** read-only fallback, повтор status/replay событий, conflict resolution; default bind остаётся loopback.
- **Сейчас / обход:** read API/gateway могут слушать сеть с token; headless CLI/Docker существуют, GUI ограничен loopback. Управляют через свой защищённый доступ к серверу.
- **Минимум:** public job API после общей модели; remote/mobile UI — эксперимент, без встроенного облачного relay.

### S34. Разобраться с IPv4/IPv6 и режимом DNS

**Кто и когда:** разработчик/power user; при различиях сетей/клиентов и dual-stack provider.

- **Вход:** hostname-proxy с несколькими DNS-ответами, нужный тип назначения IPv4/IPv6 и поддерживаемый DNS mode.
- **Действия:** сохранить hostname identity, resolved address как observation, фиксировать действительный DNS/transport path; отдельно проверить нужную address-family capability.
- **Результат:** известно, что именно проверено: family upstream endpoint и family destination не смешиваются.
- **Ошибки:** IPv6 маршрут отсутствует, разные DNS-ответы, proxy удалённо не разрешает target, exporter потерял DNS semantics.
- **Восстановление:** повторить нужный family/probe, сменить явно выбранный DNS mode, отметить network context; не подменять endpoint hostname одним вечным IP.
- **Сейчас / обход:** IPv4/IPv6 proxy literals и SOCKS5h-related parsing существуют; hostname endpoints отклоняются. Пользователь сравнивает внешними сетевыми утилитами.
- **Минимум:** наблюдаемые resolved/family поля в hostname-поддержке и точная документация транспорта; дополнительные DNS knobs только после проверки реального поведения библиотеки.

### S35. Очистить устаревшую историю, сохранив рабочие настройки

**Кто и когда:** обычный/power user; редко, при росте базы или завершении проекта.

- **Вход:** выбрать закрытую коллекцию, старые observations/export snapshots и retention rule.
- **Действия:** показать preview counts/bytes/affected scopes, предложить backup; сначала убрать membership/старые данные, не удаляя общие access/observations, нужные другим collections/pools.
- **Результат:** понятное освобождение места без потери активных проектов, secrets и контрольных настроек.
- **Ошибки:** активный writer, общие endpoints, выбран весь data scope, disk full до backup.
- **Восстановление:** перенести cleanup после job, отказаться/сузить scope; restore-copy из backup; необратимое удаление требует конкретного видимого подтверждения в продукте.
- **Сейчас / обход:** `clear-data --yes` и GUI очистка удаляют базу/профили/экспорты, сохраняя settings/denylist; export generation retention уже ограничен.
- **Минимум:** scoped retention после collections, preview и backup; не повторно создавать существующую очистку и не добавлять автоудаление по скрытому правилу.

## Проверка цельности

Одна коллекция из S04/S05 используется в S06, становится входом S07, подключается через S08/S20 и управляется S09/S10. Наблюдения S01–S03, S14–S17 и S27/S34 сохраняют разные типы доказательств, но общий контекст и freshness. S11/S12 объясняют неуспех каждого пути; S22/S30/S35 обеспечивают восстановление и сопровождение. S13/S24/S29 оценивают качество без смешения зеркал, количества endpoints и числа выходных IP.

Критическая граница: ни один сценарий не меняет другой collection/profile/route молча, не ослабляет правила ради ненулевого результата и не делает скрытый DIRECT при пустом пуле. Дополнительные продвинутые S16/S17 и экспериментальный S33 не блокируют законченную первую версию основных S01/S04/S06/S11/S12.
