# Proxy Workbench: состояние после первого workflow

**Уточнение происхождения изменений:** пользователь отдельно менял дизайн. Этот документ описывает совокупное состояние рабочего дерева; изменения дизайна и визуального оформления не являются заслугой workflow. Без отдельных commits и отчёта исполнителя нельзя достоверно приписать каждую UI-правку конкретному автору. Для оценки workflow учитывать подтверждённые изменения поведения/backend/поставки, сохраняя дизайн пользователя.

Срез: 25 сентября 2026. Основная рабочая копия — `proxy-workbench`, ветка `main`, последний commit `e4bf03c`, версия 2.2.1. Изменения первого цикла находятся в рабочем дереве, а не в новом опубликованном релизе. Разработка источников идёт отдельно в `sources-catalog` / `proxy-workbench-sources` и в этот результат не включена.

**Вывод:** есть полезные изменения интерфейса, экспорта, сохранности перепроверки и подключения клиентов. Но полный первоначальный план не реализован. Несколько новых механизмов работают лишь частично, а часть прежних проблем осталась. Следующий шаг — закончить согласованность результата и объединить источники, затем развивать поиск, профили и постоянные пулы. Авторизованные провайдеры полезны отдельным следующим этапом; для заявленной цели пользователя они не должны отодвигать обычный бесплатный поиск на несколько релизов.

## 1. Метод и ограничения

Изучены текущие изменения кода относительно `e4bf03c`, вызывающие пути scanner/GUI/API/gateway/export, launchers, packaging, CI, новые и изменённые тесты. Сопоставлены итоговые материалы продуктового исследования 00–08, 28 карточек и 35 сценариев. Ветка источников просмотрена только для определения статуса и границ интеграции; её незавершённые изменения не объявляются готовыми.

Тесты и сканирования в этой проверке не запускались: `AGENTS.md` требует отдельного запроса на тесты и сетевые проверки проекта. Посчитаны определения тестов и прочитаны сценарии; это не отчёт об их прохождении. Исходники и пользовательские данные не изменялись.

Открытая вкладка Safari с Proxy Workbench была просмотрена без запуска операций. Она сообщала «Нет связи с приложением». Структура текущей формы доступна, но надёжно оценить отрисовку всех экранов и работающий backend по такой вкладке нельзя. Визуальную приёмку нового релиза ещё нужно выполнить после запуска согласованной версии.

Состояние: 25 изменённых tracked-файлов и дополнительные untracked документы/тест QR; 154 определения тестов в 19 файлах против 121 в 18 файлах исходной версии. Изменения составляют около 14 тысяч добавленных строк, значительная часть — UI. Это объём diff, не показатель готовности и не доказательство плохого кода. Некоторые UI-изменения существовали ещё до первого аудита; без отдельных commits нельзя точно приписать весь diff одному workflow.

Статус «есть» означает прослеженный путь в коде; фактический запуск, качество публичных прокси и готовность установленных сборок в этом аудите не подтверждались.

## 3. Какие текущие технические решения стоит сохранить

1. Сохранён стек и рабочий scanner; не создан второй независимый движок.
2. Убрано удаление всех прежних результатов перед перепроверкой: остановка больше не должна стирать ещё не заменённые payload.
3. API переведено к чтению согласованного поколения, добавлены причины частичного результата, отсутствующего/повреждённого экспорта.
4. Export-фильтры стали ближе к таблице; появились реальные обработчики выделенного списка и denylist.
5. Непроверенная репутация обозначается как unknown.
6. Учёт sources больше не ограничивается исключительно первым источником, а country/search не портят source-quality автоматически.
7. Подключение приложений стало понятнее: отдельный gateway-раздел, recipes и QR. Ограничение TCP хотя бы отражено в текстах.
8. Улучшены завершение фоновых обработчиков, диагностика launchers и переносимость smoke.

Эти изменения стоит сохранить и довести. Завершение workflow означает окончание его выполнения, а не закрытие всех требований исходного большого запроса.

## 4. Существенные проблемы, которые остались или появились

Ниже — выводы по коду. Условия проявления описаны для будущего локального воспроизведения; тесты этого аудита не выполнялись. Приоритет «до релиза» не является классификацией внешней уязвимости.

### R01. Freshness не проходит весь путь scanner → БД → выдача

**До релиза.** `proxy_workbench/proxytool.py:1089` добавляет `valid_until`; реальные вызовы находятся в export. `scan.store()` около строки 1380 сохраняет payload без этой отметки; `row_fresh()` около 1108 считает отсутствие поля свежим без срока. Затем обычный scan пропускает такие записи как done около строки 1339.

Сценарий: scan сохранил хороший адрес → прошло больше срока годности → обычный run/continue пропускает прежний payload → export исключает адрес по `checked_at + TTL` → список пуст, хотя новой проверки не было. Меняется также TTL при новом export с другим watch, поскольку исходный payload не содержит зафиксированной политики.

**Нужно:** одна freshness-policy по времени измерения/версии условий; одинаковый расчёт для БД, scan queue, GUI, API и gateway; legacy rows с известным `checked_at` мигрировать, неизвестное время не подменять временем публикации. Отдельный тест должен начинаться настоящим `scan()`, а не вручную вставленной строкой с `valid_until`.

### R02. Первый истёкший адрес опустошает весь snapshot

**До релиза.** Export вычисляет общий `valid_until = min(exported_valid_until)` (`proxytool.py:1867`). `api.Exports.load()` сначала фильтрует rows индивидуально, но затем возвращает пустой список при истечении общего status (`api.py:155`, конец load).

Сценарий: один адрес годен ещё минуту, другой — час. Через минуту потребитель получает пустой пул, хотя второй свежий.

**Нужно:** оставлять свежих участников; отдельно считать oldest/newest/expired_count и состояние всего пула. Не маркировать пустой впервые созданный результат как «истёкший»: отсутствие подходящих и expiry — разные причины.

### R03. Таблица и скачивание всё ещё заблокированы во время scan/watch

**До релиза.** `gui.App.results()` около 669, `detail()` около 788 и `Handler.do_GET()` около 1000 берут `workbench.lock`. Worker держит его во время задания, включая ожидание watch. Сам UI пытается обновлять результаты во время scan.

**Нужно:** read-only snapshot/WAL без эксклюзивного writer-lock; скачивать файл выбранной immutable generation без удержания lock на время передачи. Зафиксировать поколение один раз, а не повторно читать указатель между проверкой status и open файла.

### R04. Экспорт выделенного меняет общий рабочий пул

**До релиза.** `app.js:4204` запускает обычный `export` с selection; worker публикует новый `current.json` (`proxytool.py`, конец export). Его читают API/gateway. `gui.results()` ограничивает таблицу members текущего export (`gui.py:631`, затем `visible`).

Сценарий: в пуле 100 адресов → выделить 2 для скачивания → активная выдача и таблица сокращаются до 2. Кнопка с подписью «Скачать» фактически запускает пересборку общего экспорта, а не отдельную загрузку.

**Нужно:** разделить активную публикацию пула и временный файл выбранной выборки. Изменение фильтра/скачивание не должны переключать подключённое приложение. Таблица хранит доступ ко всему выбранному scope, а не только к последнему top-N export.

### R05. GUI может обойти отказ snapshot-reader

**До релиза.** `App.results()`/`detail()` считают наличие поколения через успешный `current_generation_name` или profile в status. Если pointer повреждён/отсутствует, но generations уже существуют, API-reader возвращает empty; GUI может счесть это legacy-режимом и перейти к SQLite/last-profile. Там строки без TTL по-прежнему fresh.

**Нужно:** различать «legacy без generations» и «повреждённая новая публикация» через явное состояние reader. Не делать fallback к произвольным строкам БД во втором случае.

### R06. Собственный hostname принимается формой, но отбрасывается сборщиком

**До релиза или явно убрать обещание поддержки.** `gui.validate()` использует `normalize_custom_list()` (`gui.py:168`), разрешающий hostname/private адреса. Однако collect.add (`proxytool.py:650`) по-прежнему вызывает `normalize()` только для публичных IP. GUI test/selection также применяют public-only normalizer.

**Нужно:** одинаковая модель endpoint и scope на всём пути. До завершения — честно отклонять неподдерживаемый импорт, а не успешно сохранять его и затем терять. Credentials по-прежнему запрещены. Именованных коллекций, isolated import и secret store нет.

### R07. Watch всё ещё только уменьшает пул

**Главная следующая функция.** Цикл около `proxytool.py:2500` повторяет только `recheck_passing=True`. Нет нового collect/refill, резерва и возврата отвалившихся. Find-N при первом запуске не превращается в desired-state controller.

**Нужно:** минимальный контроллер N + резерв + refill budget + cooldown + причины недобора. Пустой пул должен восстанавливаться в своём scope. Для этого не требуется сначала внедрять весь secret-store или мобильный клиент.

### R08. Анонимность всё ещё может быть ложной

**До релиза.** `anonymity.classify()` около строки 99 не подтверждает формат judge и наблюдаемый IP перед `elite`. В scan/export/results требование anonymity всё ещё сбрасывается до any при отсутствии judge.

**Нужно:** валидируемый echo; пустой/посторонний ответ → unknown; обязательный фильтр без нужной пробы → объяснимая ошибка. Это не исправлено изменением reputation default на unknown.

### R09. IPv6 DNSBL и коды ошибок не исправлены

**До релиза соответствующих обещаний.** `reputation.py:180` всё ещё разворачивает `address.exploded` с двоеточиями; `check_dnsbl` считает любой `127.*` listed. Нужны dotted nibbles и zone-specific outcome mapping. Smart preset теперь использует конкретные DNSBL, поэтому корректность их ответов стала ещё важнее.

### R10. Измерение Mbps прежнее

**До релиза сильных обещаний о скорости.** `proxytool.py:1164` всё ещё считает байты первого chunk, начав interval после его получения. Для короткого ответа интервал практически нулевой.

**Нужно:** правильное окно измерения, минимальные объём/длительность и insufficient-sample; отдельные transfer/TTFB. Нельзя связывать такой замер с гарантией 4K-видео.

### R11. Gateway reservation и handshake deadline остались незавершёнными

**До релиза.** `gateway.py:336` выбирает proxy, ждёт open_tunnel, затем acquire: параллельные connect могут превысить max-per-proxy. `handle()` ограничивает ожидание первого байта, но не всего HTTP/SOCKS handshake (`gateway.py:400`).

**Нужно:** резервировать слот до await с release на cancel/error; общий конечный deadline handshake и bound на входящие соединения. Нынешний `test_per_proxy_limit` проверяет последовательные pick/acquire и не ловит этот interleaving.

### R12. LAN включён по умолчанию и использует тот же секрет, что GUI

**Нужно изменить перед массовой desktop-поставкой.** `gui.py:1091` default gateway bind теперь `0.0.0.0`; около 1134 gateway password присваивается `server.app.token`. QR делится паролем подключения с телефоном, а это одновременно секрет управляющего GUI. Loopback GUI сам по себе не стал доступен из LAN, но границы двух возможностей связаны одним secret.

**Нужно:** отдельный gateway-token; понятный opt-in LAN, видимое состояние и выбор интерфейса; локальный default остаётся локальным. Авторизация LAN есть — это не утверждение об открытом неавторизованном proxy. QR не является шифрованием канала или VPN.

### R13. Denylist не отзывает уже выданный пул немедленно

**До релиза группового «запретить».** `add_denylist()` сохраняет settings/file и обновляет таблицу, а API/gateway читают прежнюю generation. Кнопка формулируется про будущие проверки/экспорты; полного revoke сейчас нет. Кроме того, TCP-prefilter выполняется до screen_proxy для ранее накопленного запрещённого адреса.

**Нужно:** различать «запретить впредь» и «отозвать из активного пула», инвалидировать соответствующие admissions и проверять denylist до любого connect. Закрытие уже существующих streams — отдельная явно выбранная policy.

### R14. Fail-closed sing-box нуждается в versioned validation

**До релиза экспорта для заявленного клиента.** `formats.py:93` создаёт `type: block`; официальный migration guide относит special outbounds к legacy и показывает переход на rule actions. Наличие JSON и unit assertion `type == block` не доказывает принятие конфигурации пользователем. [Официальная миграция sing-box](https://sing-box.sagernet.org/migration/#migrate-legacy-special-outbounds-to-rule-actions).

**Нужно:** определить поддерживаемые версии, генерировать совместимый reject и проверять установленным закреплённым клиентом. Сам отказ от скрытого DIRECT — правильное изменение, его сохранять.

### R15. Скачивание через Chromium всё ещё закрывает stream дважды

**До релиза browser-пути.** `app.js:4109`: fetch → showSaveFilePicker → pipeTo → writable.close. `pipeTo` по умолчанию закрывает destination; picker также зависит от пользовательской активации. Это прежний дефект, не исправленный новым оформлением кнопок. [MDN: pipeTo](https://developer.mozilla.org/en-US/docs/Web/API/ReadableStream/pipeTo), [MDN: showSaveFilePicker](https://developer.mozilla.org/en-US/docs/Web/API/Window/showSaveFilePicker).

**Нужно:** picker в допустимый момент, одно закрытие, отдельная обработка cancel и рабочий fallback.

### R16. Источники в main улучшены лишь частично

URL каталога `branding.py:18` всё ещё смотрит в корень вместо package-path. Display-name теперь host + hash, а не имя publisher/feed. Country resolver строится до collect (`proxytool.py:2389`), поэтому свежая Geonode metadata не попадает в его snapshot в том же запуске. Prune сохраняет необратимое удаление по ≥20 checks последнего профиля; прочитанный status не пересчитывает age сам.

**Нужно:** передать эти замечания при приёмке источников, не заводить конкурирующую реализацию. Ветка sources уже меняет эти части; её нельзя оценивать как завершённую до итогового diff.

### R17. Smart presets и «живая лента» сильнее реального backend

`app.js:4323`: Telegram preset обращается к telegram.org; YouTube — к главной странице и отдельному Cloudflare speedtest. Это не проверка MTProto/видеосегментов. Несколько presets меняют только часть полей: после Elite при переключении сценария могут сохраниться judge/strict/anonymity-условия.

`app.js:2939` ticker ищет OK/PASS/FAIL в обычном логе. Основной scan публикует агрегированные строки, а не события каждого proxy с latency. Поэтому обещанная лента адресов не подключена к полноценному потоку измерений.

**Нужно:** versioned profile presets с явным составом и сбросом/сохранением полей по определённой политике; точные названия; structured recent results/events вместо извлечения состояния regex из текста.

### R18. Быстрый тест — диагностический, не обновление пула

`gui.py:803` берёт существующий profile, выключает anonymity/speed, вызывает check_proxy без reputation pipeline и не сохраняет observation. Timeout ограничен на запрос, а attempts × targets может оставаться большим; полного короткого deadline на весь вызов нет. UI показывает OK/latency рядом со старой строкой.

**Нужно:** подписать объём теста; предложить отдельно «полная перепроверка с обновлением»; ограничить весь запрос и согласовать fail-fast threshold с выбранным порогом. Не освежать прежнюю карточку как будто проверены все условия.

### R19. Desktop-цель не закрыта

`paths.py` и PyInstaller spec не изменены: frozen пишет рядом с executable, console=True. Release-job для Mac отсутствует. `docs/packaging/README.md` честно объясняет, что `.app/.dmg` и signing/updater не существуют.

**Нужно:** per-user paths и portable choice → минимальная самодостаточная `.app` → проверка packaged resources/worker lifecycle → signing/notarization при наличии ключей. Нативное окно можно добавлять отдельно. Включение Mac wheel в CI не заменяет этот результат.

### R20. Инженерная приёмка и документация отстают от объёма изменений

`CHANGELOG.md` оставляет Unreleased пустым, версия 2.2.1 не менялась. README обновлён мало при существенном изменении поведения. Нет подтверждения выполнения cross-platform CI по текущему незакоммиченному дереву. QR-test проверяет SVG/структурные строки, а не декодирование QR. Полноценного browser E2E suite не обнаружено.

**Нужно:** собрать текущий итог в reviewable commits после сохранения исходных пользовательских правок; конкретные regression cases R01–R18; browser-flow checks; QR encode/decode; actual client config validation; release notes и матрица проверенных сборок. Не увеличивать тестовую статистику проверками, повторяющими implementation.

## 5. Интерфейс и удобство

В текущей структуре шесть разделов: Проверка, Результаты, Ротирующий шлюз, Мобильные клиенты, Источники, Как это работает. Есть тёмная/светлая темы, EN/RU, карточки сценариев, country combobox, быстрые сервисы, выделение, подсветка latency, progress gauge, журнал и recipes.

**Удачные изменения:** страны можно находить по имени; действия строки видны; копирование и подключение собраны понятнее; расширенные поля частично спрятаны. Это стоит сохранить.

**Что мешает обычному пользователю:** по-прежнему сначала предлагаются сервисы, пороги, ранжирование и анонимность; нет простого выбора цели «собрать / найти обычные / мои прокси / выбранные сервисы». Названия Elite Privacy, 4K и «проверенно чистый IP» чрезмерно уверенные. Источники пока textarea с 55 URL. Нет проекта/коллекции, библиотеки профилей, полной истории, объяснения нулевой выдачи.

В коде UI стало около 4 470 строк JS, 7 082 CSS, 1 609 HTML. Предыдущие незакоммиченные UI-изменения уже были крупными; не следует автоматически обвинять весь рост в лишней генерации. Но следующую работу стоит направить на законченные сценарии и единые данные, а не ещё один слой анимаций и CSS override.

Тема и язык всё ещё сохраняются в localStorage случайного loopback origin; серверные настройки предпочтений не появились. В открытой странице встречаются английские aria/help при русском UI. Это кандидаты на полировку после функциональных исправлений.

## 6. Оценка мозгового штурма

**Материалы полезные.** Они различают endpoint/access/collection/profile/job/pool, не выдают HTTP-пробу за весь сервис, правильно требуют сохранного recheck, стабильной привязки клиента, совместимых экспортов и секретов по всему пути. 35 сценариев и 28 карточек дают разработчику приёмку, а не только названия фич.

**Главное несогласие — порядок, а не содержание.** Предложенный R1 ставит hostname/auth/OS vault и несколько сложных credential-транзакций в ближайший большой релиз; basic-режим, каталог сервисов, параметры и быстрый публичный пул уходят дальше. Пользователь неоднократно подчёркивал именно бесплатный поиск, страны, набор сервисов, скорость и полноту функциональности. Наличие ограничения BYOP в коде не доказывает, что его устранение важнее этих сценариев.

План сам признаёт альтернативу public-pool-first разумной. Для этого проекта сейчас выбираю её, сохраняя универсальную основу scope/freshness/migrations. Полную auth-поддержку не выбрасывать, а выделить отдельным завершённым этапом после неё.

### Что исправить в готовом промпте 07 перед запуском

1. В STEP 0 включить текущие R01–R20 и итоговый commit источников после завершения их workflow.
2. Зафиксировать, что `freshness`, country picker, row actions, поколения и LAN уже частично реализованы: их чинить/переиспользовать.
3. Из R1b hostname/auth сделать отдельный этап, а basic/catalog services/profiles/maintain-N поднять в пользовательскую очередь.
4. Не вводить жёсткие 300 секунд как «доказанный оптимум». Это гипотеза; общий visible max-age и механизм recheck важнее числа. Слишком короткий срок без refill превратит текущий scan в часто пустой пул.
5. Не делать полную библиотеку профилей/очередь/secret vault обязательной архитектурой одного небольшого исправления.
6. Source workflow считать владельцем каталога/adapters/cache. Согласовать schema миграций, provenance и импорт перед объединением.
7. Mac packaging сделать отдельным параллельным результатом; подпись зависит от владельческих ключей, сам bundle — нет.

## 7. Порядок дальнейшей работы

### Этап A — закончить приёмку текущей версии

Сохранить её отдельной согласованной ревизией. Исправить сквозной TTL, mixed-age snapshot, чтение при scan/watch, экспорт выделенного без смены пула, импорт hostname mismatch, judge/DNSBL/bandwidth, gateway concurrency/deadline, browser download. Сделать LAN opt-in с отдельным token. Обновить фактические пользовательские обещания.

Выход: локальные regression-сценарии и нормальная работа существующего приложения без новых крупных функций. Это исправление основы для всех следующих направлений.

### Этап B — принять источники и объединить аккуратно

Sources-worktree основан на commit `806d13d`, который скопировал промежуточные изменения main. С тех пор main продолжил меняться. Оба направления затрагивают как минимум `api.py`, `gui.py`, `proxytool.py` и все три UI-файла. Простое копирование файлов обратно затрёт часть завершённых исправлений.

Нужно: зафиксировать main → получить конечный sources diff относительно его baseline → применить по смыслу → проверить общие контракты/config migrations → выполнить интеграционную приёмку. Наличие 20 тысяч строк JSON или новых `source_*` модулей в незавершённой ветке не доказывает готовность.

Выход: весь каталог доступен с честными статусами; базовый/расширенный наборы; parser preview; metadata hints; cache/last-good; provenance; одинаковое управление из GUI/CLI. Источник доступен — не значит, что все его адреса рабочие.

### Этап C — следующий функциональный релиз под реальный запрос

Предлагаемое название: **«Найти нужные прокси и удобно ими управлять»**.

1. Явные режимы «собрать / обычные рабочие / для сервисов / мой список».
2. Каталог сервисов с категориями, поиском, несколькими выбранными и сохранёнными наборами.
3. Именованные профили, all/any/K, понятные расширенные параметры.
4. Изолированный импорт/коллекции и единый scope выдачи.
5. География: сохранить picker, добавить смысл endpoint/exit и неизвестную страну.
6. Единый max-age и объяснимая карточка результата; текущая проверка отделена от прошлого успеха.
7. Export/copy/connect выбранного scope без влияния на соседние задачи.

Реализовать несколькими небольшими интегрируемыми срезами, а не огромным переключением схемы и UI за один раз.

### Этап D — постоянный пул и ускорение

Один пул N+reserve, refill из источников и резерва, возврат после cooldown, budgets, остановка/восстановление. Затем pipeline сбора и проверки, быстрые первые результаты, несколько пулов/квоты. Полный scheduler и remote control добавлять после устойчивого локального сценария.

### Параллельный этап Desktop

Per-user paths → готовый Mac `.app`/архив или `.dmg` → проверка packed resources/workers → отдельное окно/tray при необходимости → signing/installer/update. Windows `.exe` и CLI сохраняются. Не откладывать минимальную Mac-поставку до всех auth/media/cloud-возможностей.

### Этап E — свои провайдеры и продвинутые интеграции

Hostname/auth через checker, gateway, UI, CLI и экспорт, OS vault/session secrets, смена credentials и revision invalidation. Затем subscriptions, WebSocket/media, сравнение поставщиков и расширенные schedules — по спросу. Для этой стадии подробный R1b продуктового исследования пригодится почти полностью.

## 8. Минимальные проверки перед признанием следующего результата готовым

1. Настоящий scan → продвижение времени → resume заново проверяет устаревшую запись.
2. Старый и свежий proxy в одном export: истечение одного оставляет другой.
3. Переэкспорт не освежает measurement и не меняет срок из-за случайного watch-параметра.
4. Results/details/download доступны во время активного scan и waiting-watch.
5. Export двух из ста не сокращает таблицу/активный gateway до двух без отдельного действия публикации.
6. Corrupt/missing current pointer даёт одинаковый явный unavailable в GUI/API/gateway.
7. Import hostname/private даёт одинаковое поддержанное поведение либо понятный отказ во всех путях.
8. Свой список не включает старые публичные адреса.
9. Unknown judge и DNSBL error не дают elite/clean/listed соответственно.
10. Concurrent connect соблюдает лимит; partial handshake/cancel заканчиваются в deadline.
11. Denylist прекращает новый admission и не запускает prefilter к запрещённому endpoint.
12. Файл sing-box/Clash принимается заявленной версией клиента; QR декодируется обратно в исходный fixture URL.
13. UI download/cancel/filter changes работают в заявленных браузерах; UI labels соответствуют пробам.
14. Main+sources объединённая версия проходит те же сценарии; старые настройки мигрируются.
15. `.app` запускается без Python на заявленной архитектуре, пишет вне bundle и корректно завершает worker.

## 9. Практическое решение

Первый цикл дал улучшенную основу, которую нужно принять и исправить по конкретным сценариям. Исследование продукта использовать как библиотеку продуманных функций и критериев приёмки. Источники закончить отдельным workflow и интегрировать один раз. Следующий большой запрос должен фокусироваться на обычном поиске, профилях, собственных списках и поддержании пула; auth и полноценные мобильные/TUN-возможности не подменяют эти результаты.
