### Примечания к таблице

- Полные `data_urls`, `homepage`, `documentation_url`, `terms_url`, полный `license_status`, `access_note`, `quota`, `update_claim`, `compat_note`, `priority_reason`, `unknowns` и полный блок проверки находятся только в `catalog.json`; ячейки таблицы сокращены.
- В `data_urls` каждой записи оставлен только URL, который реально сопоставлен с `verification.url` и присутствует среди проверенных кандидатов. Дополнительные URL из discovery не входят в `verification.json`, поэтому они не включены и не считаются доступными.
- Для `new-001`–`new-007`, `new-013`, `new-027`, `new-028`, `new-047`, `new-069`–`new-072` и `new-088`–`new-095` проверенный URL является страницей, документацией или конфигурацией, а не подтверждённой анонимной выгрузкой; `data_urls` содержит проверенный URL-кандидат, а отсутствие отдельного URL данных отмечено в `unknowns`.
- `family_id` обозначает семейство издателя/репозитория. `mirror_group` — отдельная группа пересечения ip:port из `overlap.json`; одинаковая группа не доказывает авторство или происхождение зеркала.
- `works_now`: текущий сборщик уже имеет URL либо может прочитать проверенную структуру существующим парсером; `parser_tweak`: нужен выбор другого data_url или изменение лимита/парсера; `new_adapter`: нужен новый форматный адаптер; `account_or_key`: нужны учётные данные/оплата; `not_compatible`: проверка или формат не позволяют принять источник сейчас.
- `license_status` различает лицензию кода и лицензию чужих IP-данных. MIT/GPL кода сам по себе не считается разрешением распространять эти записи прокси; полный вывод каждого трека сохранён в JSON.
- `new-001`–`new-007` — коммерческие предложения без подтверждённого анонимного data_url; `new-068`–`new-072`, `new-082`, `new-090`–`new-093` — своя инфраструктура/конфигурации; `new-089`, `new-091`, `new-094`, `new-095` — документация форматов, а не готовые списки.
- Учётные данные, приватные ключи, пароли и токены не включены. Для `new-026` временный подписанный query из `verification.json` сохранён дословно только как результат проверки в `final_url`; он может устареть и не является постоянным `data_url`.

## Пробелы и неизвестное

- **Liveness отсутствует:** ни один адрес из 150 ответов не проверен как прокси. Все `150` записей имеют `proxies_actually_tested=false`.
- **Нет пригодного непустого ответа (10):** `cur-37`, `new-017`, `new-018`, `new-019`, `new-020`, `new-037`, `new-053`, `new-062`, `new-082`, `new-083`. Это срез одной попытки, а не доказательство постоянной недоступности. `cur-37` отдельно: HTTP 200 с пустым телом — **пусто на момент проверки 2026-09-25T12:23:58Z**.
- **Достижимы, но без распознаваемых ip:port (18):** new-001, new-002, new-003, new-005, new-007, new-010, new-015, new-027, new-028, new-050, new-052, new-059, new-086, new-088, new-089, new-091, new-094, new-095. Для части страниц список может появиться после JavaScript или по другому data_url.
- **Редиректы (7):** cur-53, cur-54, new-013, new-025, new-026, new-052, new-067. `final_url`, число редиректов и тип ответа сохранены в `verification`; исходный URL остаётся в `verification.url` и `data_urls`.
- `new-087` вернул `declared_kind=json-invalid`, `bytes=4194304` и `curl_exit=56`; `truncated_at_cap=false` не доказывает целостность JSON.
- `cur-37`, `new-014`, `new-053`, `new-062`, `new-082`, `new-086` и другие пустые/неполные ответы нельзя считать рабочими наборами только потому, что URL отвечает. Для `cur-37` установлен только пустой срез; окончательная недоступность не доказана.
- Числовые квоты и гарантии обновления не подтверждены отдельным повторным запросом; `quota` и `update_claim` передают только формулировки треков. Наличие ETag/Last-Modified — лишь косвенный признак возможного обновления.
- Лицензии данных в большинстве записей не установлены; особенно нельзя автоматически переносить лицензию кода на IP-инвентарь. Полный текст каждого вывода — в `license_status` и `terms_url`.
- Наличие geo/ASN/anonymity/latency/timestamp определяется по проверенному payload и не гарантирует достоверность полей.
- Коммерческие quota/trial/key условия не повторно проверены: аккаунты не создавались, платёжные данные не вводились, реальные credentials в каталог не попали.
- Для `new-026` `final_url` перенесён дословно, включая временную подпись; такой destination может устареть. Исходный URL остаётся в `verification.url` и `data_urls`.

- **Историческое AST-измерение понизило совместимость 9 записей** (`new-009`, `new-011`, `new-012`, `new-023`, `new-030`, `new-048`, `new-051`, `new-065`, `new-066`): отдельно выполненные `normalize` и `loose_addresses` приняли 0 строк из тела этих источников. Это не был реальный `collect()`. Последующая локальная интеграционная проверка через настоящий `collect()` и mock-сервер подтвердила, что запланированные `json-records`, `fields`, `page-json` и `html-table` пока не существуют как `SOURCE_KINDS`, а существующие девять видов принимают назначенные сохранённые образцы. Подробности — в `notes/integration-plan.ru.md` и `tests/test_research_collect_integration.py`.
