# Proxy Workbench: 140 задач развития

Читать вместе с [аудитом](AUDIT_AND_ROADMAP.ru.md) и [каталогом источников](SOURCES.ru.md). Исправления F01–F40 из аудита предшествуют расширению связанных функций. Здесь описан конечный полезный результат задач, включая развитие уже имеющихся возможностей.

**P1:** основа следующего большого релиза. **P2:** следующая очередь после основы. **P3:** необязательное развитие по спросу. Размер: **S** — локальное изменение; **M** — несколько связанных компонентов; **L** — подсистема; **XL** — отдельный проект/этап. Это оценка сложности, не обещание сроков.

Не реализовывать все пункты сразу. Для первого релиза выбрать путь E0–E3 из аудита; P3 держать вне обязательного scope. Критерии ниже проверяются на synthetic data/local mocks и согласованной матрице ОС.

| CHK02 | P1 / M | Структурные стадии и ошибки: DNS, TCP, handshake, TLS, response, assertion | Каждая ошибка имеет code, stage и понятное объяснение; нет secrets в тексте |

## Что пока оставить за пределами плана релиза

Полноценный VPN/TUN, UDP/QUIC-routing, облачный аккаунт и синхронизация, distributed scanning, исполняемые плагины из интернета, мобильные клиенты — отдельные исследования после подтверждённого спроса. Их отсутствие не мешает выполнить основную задачу проекта: найти, проверить, организовать и поддерживать пригодные прокси для выбранного сценария.

Завершение задачи означает не только наличие кнопки: корректная бизнес-логика, диагностика ошибки, сохранение/миграция данных, необходимая проверка на заявленных платформах и короткая пользовательская инструкция.
