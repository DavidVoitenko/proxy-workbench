# F22: фоновая работа, меню-бар, один экземпляр, сон — что сделано и что осталось за мной

**Ветка:** `integration/ultra-2026-09-25`
**Мои файлы:** `proxy_workbench/desktop.py`, `packaging/launcher.py`, `docs/packaging/*`, этот файл
**Дата:** 26 сентября 2026
**Платформа проверки:** macOS 26.5.2, arm64, Python 3.14.5, Xcode Command Line Tools присутствуют

## Коротко

F22 не был реализован: `mark_wake` и `mark_awake` были написаны, покрыты
тестами и не вызывались никем. Теперь слой есть, он запускает настоящий продукт
и проверен живым запуском на macOS — 48 проверок из 48, все через `ps`, локальный
сокет и файлы. Windows и Linux: код написан, **не проверено ни разу**, и в
release notes так и написано.

Отдельным попутным дефектом был перенос старой папки: `legacy_data_roots`/
`plan_migration`/`apply_migration` вызывались только из тестов, хотя release notes
объявляли готовность. Теперь перенос подключён к `desktop.main`: один раз на
каждое изменение старой папки, с сообщением в терминал и строкой в меню.

## Что именно появилось в `proxy_workbench/desktop.py`

Всё в трёх новых секциях; существующая логика layout/migration/update/signing не
тронута, кроме подключения переноса в `main`.

| Слой | Точки входа | Зачем |
| --- | --- | --- |
| Экземпляр | `InstanceLock`, `Instance`, `read_instance`, `interface_holder` | один процесс на папку данных; второй запуск не становится вторым приложением |
| Канал управления | `ControlServer`, `control_request`, `DesktopHost.handle` | одна строка JSON — один ответ; по нему говорят и меню-бар, и второй запуск |
| Меню-бар | `TRAY_HELPER_SOURCE`, `ensure_tray_helper`, `Tray` | NSStatusItem поверх той же страницы; helper ничего не знает о продукте |
| Автозапуск | `autostart_status`, `enable_autostart`, `disable_autostart`, `set_autostart` | LaunchAgent / `HKCU\…\Run` / XDG autostart, только по действию пользователя |
| Сон, сеть | `PlatformObserver`, `network_fingerprint`, `mark_jobs_suspended`, `close_job_sleeps`, `open_schedule_engine`, `wake_tick` | единственное место, где живут обе точечные функции F11 |
| Перенос | `run_startup_migration` | один раз, с уведомлением |
| Хост | `DesktopHost`, `main`, `_host_command` | сборка всего вместе; `main` больше не уходит в `gui.main` сразу |

Новые команды хоста: `--status`, `--autostart on|off`, `--autostart-status`,
`--migrate-preview`. Новые флаги запуска: `--background` (без браузера, как
login item), `--no-tray`.

## Почему меню-бар — отдельный нативный helper, а не Python-библиотека

`rumps`, `pyobjc` и `tkinter` на этой машине нет, ставить их в зависимости
проекта я не могу (не мой файл `pyproject.toml`), а меню-бар — единственная
часть F22, которую нельзя сделать «примерно». Поэтому исходник helper'а
(около 250 строк Swift) встроен в `desktop.py` строкой и компилируется
`swiftc` один раз на машину в `<cache>/tray/`, с именем, в котором зашит
хеш исходника, — при изменении исходника он пересобирается сам.

Helper:

- рисует `NSStatusItem` и строит меню из присланных подписей (списка словарей),
  поэтому продуктовых строк не знает и ошибиться в них не может;
- раз в 2 секунды спрашивает статус и перерисовывает меню;
- пересылает `NSWorkspace.screensDidSleep` / `didWakeNotification` и изменения
  `NWPathMonitor` теми же строками JSON, что и действия;
- **умирает сам**, когда control-сокет закрывается, — это первая из трёх линий
  защиты от orphan-процесса;
- отчитывается в `<logs>/tray.log` строкой `ready {...}` — приложение знает,
  что элемент действительно создан, и не гадает.

## Три линии против orphan-процессов

1. Helper выходит, когда сокет закрылся (проверено: после `SIGKILL` приложения
   helper пропал сам, без чьего-либо сигнала).
2. `Tray.stop()` завершает helper при штатном выходе.
3. `Tray.reap()` на старте убивает helper, записанный в instance-запись
   умершего процесса; `stop_process()` сверяется с `ps`, чтобы не сигналить
   чужому pid.

## Приёмка F22 и как она закрыта

| Приёмка | Как проверено |
| --- | --- |
| Закрытие окна не убивает разрешённую фоновую задачу | страница получена по HTTP и отпущена; процесс жив и продолжает отвечать |
| «Выйти» не оставляет listeners | порт закрыт, сокет удалён, instance-запись очищена, `ps` пуст |
| Повторный запуск открывает первый экземпляр | второй запуск напечатал адрес, вышел с 0, `ps` показал `1 → 1` |
| Locked vault даёт actionable status | `describe_vault()` возвращает `session`/`locked`/`unavailable` + `action` из самого `SecretError`; фон не падает |
| Пробуждение не публикует старый пул как свежий | перенос измерений в другую сеть не трогает БД; проверено сравнением `count(*)` из `results` |
| Нет orphan-процессов | `ps` после `SIGKILL` и после `Выход` |
| После сна нет шквала catch-up | 6 проспавших часов: **5 запусков** без отметки против **1 слитого с `missed: 5`** с ней |
| Автозапуск включается только пользователем | plist отсутствует после установки и первого запуска |

## Что НЕ сделано и почему — это не мои файлы

1. **Замороженная macOS-сборка останется без меню-бара**, пока
   `packaging/build_macos.py` и `proxy-workbench-macos.spec` не положат
   helper внутрь bundle. Точная правка (две строки) — в
   `docs/integration/HANDOFF/fix-desktop.md`, раздел «Что нужно от владельца
   packaging»; сейчас frozen-сборка честно пишет, что меню-бара нет.
2. **Колонки `schedules` в `db.py`.** `SqliteScheduleStore.persists_runtime_state`
   сейчас `False`: в таблице нет `last_run_at`, `paused`, `pause_reason`,
   `wake_gap_s`. Из-за этого отметка пробуждения сливает слоты внутри процесса
   (это работает и проверено), но интервальная сетка и накопленный бюджет не
   переживают перезапуск. Это дефект F15, и `db.py` не мой.
3. **События сона/пробуждения/миграции в веб-интерфейсе.** Они пишутся в
   `data/desktop-journal.jsonl` и показываются в меню-баре, но не в странице:
   `proxy_workbench/ui/app.js` не мой. Точка подключения — см. раздел ниже.
4. **Windows.** Ни `winreg`, ни loopback-канал, ни XDG autostart не запускались.
   `time.monotonic()` на Windows включает сон, поэтому fallback-детектор там
   слепой, а нативного наблюдателя нет. Написано честно в release notes.

## Мелочи, которые стоит знать интегратору

- `main()` держит `gui.main` в главном потоке и на время работы подменяет
  `gui.make_server`, чтобы забрать ссылку на сервер: без неё нельзя показать
  статус, остановить проверку и выключиться за ограниченное время. Подмена
  узкая, снимается в `finally`, и не трогает bounded-shutdown интерфейса.
- `if __name__ == '__main__'` в `desktop.py` стоит в самом конце файла. Это не
  стилистика: при `python -m proxy_workbench.desktop` тело модуля исполняется
  как `__main__`, и блок в середине обрывал файл до определения `_write_json`
  и `_unlink`. Ошибка была `NameError: name '_write_json' is not defined` при
  первом же включении автозапуска, и она нашлась только живым запуском.
- `Job.active` — свойство, а не метод (`jobs.py:354`). Ошибка
  `job.active()` тихо ломала весь путь сна на любой реальной задаче.
- Второй запуск не поднимает вторую копию даже если первая запущена старым
  способом: `interface_holder()` смотрит на занятый `gui-instance.lock`.

## Что нужно от владельца packaging (правка не сделана, файлы не мои)

В `packaging/build_macos.py`, до вызова `pyinstaller`:

```python
from proxy_workbench import desktop
helper, reason = desktop.ensure_tray_helper(desktop.resolve_layout())
if helper is None:
    print('menubar unavailable:', reason, file=sys.stderr)
```

и в `proxy-workbench-macos.spec` в `datas`:

```python
(str(helper), 'tray'),
```

`desktop.ensure_tray_helper()` для frozen-сборки ищет
`resource_path('tray', 'proxy-workbench-tray')` и берёт его, если он
исполняемый; иначе меню-бара нет и причина попадает в статус. Сборка не
упадёт, но и не станет врать, что значок есть.

## Точка подключения для веб-интерфейса (файл не мой)

`DesktopHost.status()` уже отдаёт всё, что нужно показать в странице:
`run`, `pool`, `vault`, `platform` (последний сон, длительность, смена сети),
`autostart`, `tray`, `migration`. Если владелец `gui.py` добавит один маршрут
`GET /api/desktop` (тот же `allowed()` с токеном), страница сможет показать то
же, что меню-бар, без второго источника правды.
