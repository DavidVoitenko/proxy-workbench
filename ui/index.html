QUICK START

From a list to working proxies

Configure once. Come back to checks and results in this window.

1

Choose services

Enter the URL of every service you need. A proxy is selected only if it works with all of them. Code 200 is a normal successful response; for APIs that use other codes, specify your own.

To guard against placeholder pages, specify text that must appear in the response. Redirects are not followed: use the final URL.

2

Set the request profile

The preset sets only User-Agent and Accept/Accept-Encoding. It is part of the check profile, so changing it creates separate results. Personal values are never added automatically.

This is technical identification of the HTTP request, not browser impersonation, TLS/JA3/JA4 masking or a guarantee of anonymity.

3

Check cleanliness

The local denylist matches IPs, CIDRs and exact addresses. DNSBL flags responses from public blacklist zones; in strict mode an unknown response is not treated as clean.

DNSBL is enabled manually and uses DNS queries only. The list and zones are stored locally in data/.

4

Pick the best and download

“By speed” puts the lowest latency first. “By quality” balances success rate, speed and jitter. Enter any number; 0 keeps every matching proxy.

TXT contains the addresses, CSV the ranking table, JSON detailed request results and safe cleanliness statuses.

Good to know

This measures availability and response time, not throughput in Mbit/s. A public proxy may stop working after the check: use “Recheck” for fresh results.

New URLs, measurement parameters, request profile or cleanliness policy create a separate profile. Settings and history are stored locally. Closing the tab does not stop the application; to exit, press Ctrl+C in its terminal window.

Deletes the database, profiles and exports but keeps settings and the denylist. Local results cannot be restored.
